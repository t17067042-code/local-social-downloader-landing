A receipt file next to every local media output

A download folder full of mp4 and jpg files is not a pipeline. Six months later nobody can say which URL produced a file, whether the rights basis was recorded, or whether the bytes on disk still match what the job wrote. A sidecar receipt fixes that without a database and without uploading the media anywhere.

Process only media you created, media a client authorized you to handle, or other content you already have a legal basis to process. Platform Terms of Service still apply. This note does not describe platform endpoints, session cookies, or any way around access controls.

1. Write the media, then the receipt

Name the output by a hash of the source URL plus the job id, not by the page title. Titles collide. Write the file to a temporary name in the same directory, fsync, then rename. Only after the rename succeeds, write name.receipt.json beside it. A crash between the two leaves a media file with no receipt, which the next run should treat as incomplete and not as success.

{
  "schema": "local-media-receipt/1",
  "job_id": "2026-10-07-0042",
  "source_url": "https://example.com/post/you-own",
  "platform_label": "pinterest",
  "rights_basis": "client_authorized",
  "rights_note": "client brief 2026-09-30, campaign archive",
  "written_at": "2026-10-07T08:12:11Z",
  "output_name": "9f2c1a88b0e4d6c1.jpg",
  "sha256": "b1946ac92492d2347c6235b4d2611184...",
  "bytes": 240112,
  "tool": "local-social-media-downloader-pro",
  "tool_version": "1.2"
}

2. Fields that are allowed to be empty, and fields that are not

FieldRule
rights_basisRequired. Allowed values in this schema: own_content, client_authorized, license_on_file. Anything else is a hard stop before the tool runs.
rights_noteOptional short pointer to your own brief or license file. Do not paste private contracts in full.
sha256 / bytesRequired, computed on the renamed file, not on a buffer you still hold in memory.
platform_labelA label your script derived from the host. Not a promise that every URL on that host works.
source_urlThe URL you were authorized to process. Do not store cookies or private-account identifiers next to it.

3. Verify before the next script touches the file

import hashlib
import json
from pathlib import Path

ALLOWED = {"own_content", "client_authorized", "license_on_file"}

def verify(media: Path, receipt: Path) -> None:
    meta = json.loads(receipt.read_text())
    if meta.get("schema") != "local-media-receipt/1":
        raise SystemExit("unknown receipt schema")
    if meta.get("rights_basis") not in ALLOWED:
        raise SystemExit("missing rights basis")
    if meta.get("output_name") != media.name:
        raise SystemExit("receipt points at a different file")
    digest = hashlib.sha256(media.read_bytes()).hexdigest()
    if digest != meta.get("sha256"):
        raise SystemExit("bytes changed since receipt")
    if media.stat().st_size != meta.get("bytes"):
        raise SystemExit("size changed since receipt")

A captioner, resizer, or archive step should call this first. If verification fails, do not overwrite the file. Move both the media and the receipt into review/ and stop.

4. Idempotent reruns

Before calling the downloader, look for a receipt whose job_id matches and whose hash still verifies. If it does, skip the network call. If the media exists and the receipt does not, do not assume the file is good. Quarantine it. If the receipt exists and the media does not, treat the job as failed and write a new attempt under a new job id rather than reusing the old receipt.

This pairs with the job-log contract: the log says what the attempt did, the receipt says what file is safe to hand forward. Rights still get checked first, as in the rights-check note.
