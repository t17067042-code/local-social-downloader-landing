A preflight dry-run before any local media fetch

A local media script should be able to answer “what would this job write, and why would it refuse?” without touching the network. The rights gate, the job log, and the output receipt already cover later stages. This note is the step before those: a dry-run that only reads your job file and prints a plan.

Use this only for media you created, media a client authorized you to handle, or other content you already have a legal basis to process. Platform Terms of Service still apply. This page does not document private endpoints, cookies, or access-control bypasses.

1. Dry-run means no socket

A flag named --dry-run is not a dry-run if the process still resolves the URL. The preflight should parse the job, check the rights field, check the host against an allowlist you maintain, and print the planned output path. It should exit before any HTTP client is constructed.

import json
import sys
from pathlib import Path
from urllib.parse import urlparse

ALLOWED_RIGHTS = {"own_content", "client_authorized", "license_on_file"}
ALLOWED_HOSTS = {
    "www.instagram.com",
    "www.tiktok.com",
    "www.pinterest.com",
}

def preflight(job_path: Path) -> dict:
    job = json.loads(job_path.read_text())
    if job.get("rights_basis") not in ALLOWED_RIGHTS:
        raise SystemExit(2)
    host = urlparse(job.get("source_url", "")).hostname or ""
    if host not in ALLOWED_HOSTS:
        raise SystemExit(2)
    return {
        "action": "plan_only",
        "job_id": job.get("job_id"),
        "host": host,
        "rights_basis": job["rights_basis"],
        "planned_dir": "out/",
        "network": False,
    }

if __name__ == "__main__":
    plan = preflight(Path(sys.argv[1]))
    print(json.dumps(plan))

Exit code 2 stays “do not retry,” same as the rights note. A missing field and an unexpected host are both policy failures, not transient errors.

2. What the plan is allowed to say

FieldRule
actionAlways plan_only in this step. A later command does the fetch.
networkMust be false. If a test sees a socket open, the dry-run is broken.
hostTaken from the URL you supplied. Not proof that the URL is supported.
planned_dirA directory your script owns. Do not invent a filename until the real run knows the extension.
rights_basisEcho the value you already checked. Do not infer it from the URL.

3. Keep the allowlist in your repo, not in the tool

Supported-workflow labels on a product page are not an allowlist. Put the hosts you are willing to pass into the tool in the same repository as the job files, and review changes to that list. A dry-run that accepts every https URL is only a parser.

If a host is not on the list, stop. Do not “try it and see.” Unsupported is a valid result.

4. Hand off only after the plan matches the job

The fetch command should read the same job file, refuse if rights_basis or host would fail preflight, and write the job log and receipt only after a real write. Re-running preflight must not change out/. Re-running a successful job should hit the receipt and skip the network, as described in the receipt note.
